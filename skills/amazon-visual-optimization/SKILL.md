# Amazon Marquee Visual Director

本 Skill 是可供 Agent 遵循的任务执行说明，不依赖尚未实现的 API 或数据库。默认 Amazon 美国站，中文分析、英文图片文案和 Prompt。图片生成、发布和经营数据接入不属于默认执行动作。

## 产品定位与边界

专门服务 **Amazon 美国站 KT 板发光灯牌**，仅覆盖：

1. 数字发光灯。
2. 字母发光灯。
3. Birthday marquee numbers。
4. Wedding marquee letters。
5. Proposal marquee lights。
6. Graduation / Holiday marquee lights。

Visual Benchmark Library v0.1 增加 `heart-light` 形态标签，仅在产品资料确认其为 KT 板心形灯牌时适用，仍限 Amazon US KT 板灯牌；不得据此引入霓虹、金属或其他灯具。生日、求婚等已有产品定位保留。

活动知识库补充 Baby Shower 用途，仅用于同一 KT 板数字 / 字母灯牌，不扩展产品类别。开放框架款仅在资料证实为 KT 板灯牌且结构已确认时适用。

后四项是同一灯牌产品的活动用途，不代表其他产品类别。场景装饰只能作为环境，不成为分析或售卖主体。其他站点或非 KT 板发光灯牌请求超出本 Skill 范围，明确说明边界，不生成相应品类方案。

先确认材质、售卖 SKU、具体字符与组合、数量及活动用途；材质未确认时整理输入并将方案标记草案，不擅自认定为 KT 板。保留目录 `skills/amazon-visual-optimization/` 作为原路径，Skill 标识与显示名称按本文件更新。

本定位是现有通用架构在灯牌品类上的限定应用，不能因工作流或历史文档出现“品类”等通用字段而扩展到其他 Amazon 产品。

## 使用前读取

1. 阅读仓库根目录 [AGENTS.md](../../AGENTS.md)，遵守产品保真、证据、主辅图边界、80/20 策略和数据口径规则。
2. 旧 Listing 使用 [差转优工作流](workflows/bad-to-good-workflow.md)；新品使用 [新品工作流](workflows/new-listing-workflow.md)。
3. 根据工作流加载相关模板，不需要为单次任务读取全部架构文档。
4. 阅读 [行业知识库索引](../../knowledge-base/README.md)，按实际产品结构、活动和需求选读相关条目；Step 1 使用视觉规则，Step 2–3 将场景与产品判断作为待验证依据。报告引用条目路径和章节，同时关联实际图片证据，不能把基础框架当作已验证市场结论。
5. 需要标杆参考时读取 [Benchmark 案例索引](../../case-library/benchmark-cases/index.md)，按活动、产品、人群、图片角色和事实约束匹配，再打开选定案例全文。输出主参考 / 条件参考 / 方法借鉴 / 不适用及理由；允许无匹配。BM-004 始终保持组级关联，不能将标杆匹配当作市场或经营效果验证。
6. 使用下方 Visual Quality Rules 检查当前图与选定参考，解释优秀点和缺陷，再将结论写入设计方案与验收。标杆等级不能跳过规则检查。
7. 产品分析阶段使用下方产品专属规则，先确认尺寸、材质和灯色，再检查人物比例。暖黄 / 白灯规则按实际 SKU 选择，未知不默认暖黄。
8. Benchmark 匹配使用 [BMR-SELECTION 案例匹配规则](../../knowledge-base/benchmark-rules/benchmark-selection-rule.md)，结合产品、年龄阶段、图片用途和有依据的消费者心理需求筛选。每次必须说明为什么选择、借鉴哪些视觉元素、哪些元素重新设计；只借鉴构图、关系、色彩与光影方法，不复制人物、装饰、文案或产品比例。2FT 与 2.3FT 分开记录，缺少适配案例时允许条件参考、方法借鉴或无匹配。
9. 设计构图时读取 [Creative Composition 原则](../../knowledge-base/creative-composition/composition-principles.md)、[商业场景技巧](../../knowledge-base/creative-composition/creative-techniques.md)与[构图选择规则](../../knowledge-base/creative-composition/composition-selection-rule.md)。先按图片角色，再按事件、产品与年龄需求选择主 / 辅方法；输出选择理由、布置、独立重设计项和验收条件，不复制 Benchmark。构图选择发生在 Benchmark 匹配后、Visual Quality Rules 检查前，并写入设计 Brief 与 Prompt；没有适配案例时仍可独立选择方法。
10. 需要真实评分图片时读取 [Visual Benchmark Library v0.1](../../case-library/visual-benchmark-library/README.md)与[检索逻辑](../../case-library/visual-benchmark-library/retrieval-logic.md)，使用已登记、已复核且授权的原图与 metadata.json。先事实 / 用途过滤，再按任务相关性排序，老师分数不能覆盖场景不匹配。空库返回无匹配，不能虚构图片；候选实际查看后才进入视觉方案。新单图评价使用[六维量表](../../case-library/visual-benchmark-library/visual-evaluation-rules.md)，输出 visual_quality_score 与覆盖率、硬约束和证据，独立于老师分及旧量表；不替代旧量表的图片组检查。
11. 导入用户放入 images/ 的新图片时使用 [Benchmark Case Importer](../../case-library/visual-benchmark-library/importer.md)。默认只创建 pending 记录、像素测量与文件名候选；老师分保持未知。显式配置视觉模型后才可进行外部图片分析，结果需人工复核，不能自动授予评分等级、KT材质事实、授权或首图合规。

## 产品专属规则：产品分析前置检查

产品分析执行 **尺寸判断 → 材质判断 → 灯光判断 → 比例判断**，将结果作为 Benchmark 匹配、场景方案和 Prompt 的事实约束。

| 判断项 | 规则入口 | 必须产物 |
| --- | --- | --- |
| 尺寸判断 | [PR-SIZE-SCALE](../../knowledge-base/product-rules/size-scale-rule.md) | 4FT / 3FT / 2.3FT 或实际 SKU 高度、宽厚、单位、来源；未确认项 |
| 材质判断 | [PR-MATERIAL](../../knowledge-base/product-rules/marquee-material-rule.md) | KT 板本色、正面、真实厚度、围边 / 无围边、支撑与开放结构约束 |
| 灯光判断 | [PR-WARM-LIGHT](../../knowledge-base/product-rules/warm-light-rule.md) / [PR-WHITE-LIGHT](../../knowledge-base/product-rules/white-light-rule.md) | 实际灯色、灯点、环境光、人物 / 地面反馈，不改色项 |
| 比例判断 | PR-SIZE-SCALE 与已确认人物 / 场地资料 | 站姿 / 坐姿、身高或参照来源、地面与透视、尺度限制及验证状态 |

未知身高不能证明产品到胸口 / 肩部；4FT 的 122 cm、3FT 的 91 cm、2.3FT 的 70 cm 都按实际资料与姿态核对。没有相关资料时允许条件策划，但不声称比例已认证。

每项输出规则 ID、事实来源、已确认 / 用户陈述 / 未知 / 冲突、生成保留项、待补项和验收方式。成图另用通过 / 未通过 / 待执行 / 无法判断 / 不适用记录检查结果。明确结构与灯色约束同步进入 Step 5 的 Brief、Step 6 的 Prompt 和 Step 7 的验收，不从参考案例反向替换本品规格。

## Visual Quality Rules 模块与设计流程

```text
产品分析（尺寸 → 材质 → 灯光 → 人物与产品比例）
→ Benchmark 匹配（允许无匹配或条件匹配）
→ Visual Quality Rules 检查
→ 输出设计方案
→ AI Prompt
→ 实际成图后复查与验收
```

该流程贯穿原有七步，不删减市场判断、差异化和优先级。先独立观察当前图，再匹配参考并检查双方，不为了追随标杆改变已确认事实。

| 规则 | 目的 | 七步接入 |
| --- | --- | --- |
| [VQR-FOCUS 产品中心](../../knowledge-base/visual-quality-rules/product-focus-rule.md) | 产品 / 人物 / 装饰层级，真实尺度与结构 | Step 1、4、5、7 |
| [VQR-REALISM 真实感](../../knowledge-base/visual-quality-rules/realism-standard.md) | 人物、物品、空间与物理关系 | Step 1、5、6、7 |
| [VQR-COMPOSITION 构图](../../knowledge-base/visual-quality-rules/composition-rule.md) | 位置、互动、前中背景和景深 | Step 1、3、5、7 |
| [VQR-LIGHTING 灯光](../../knowledge-base/visual-quality-rules/lighting-rule.md) | 灯色、灯点、环境受光和地面反馈 | Step 1、5、6、7 |
| [VQR-MAIN-IMAGE 主图](../../knowledge-base/visual-quality-rules/amazon-main-image-rule.md) | 图片位置、官方前提、识别与用途优先级 | 输入准备、Step 1、4、5、7 |

每项检查输出：规则 ID → 图号 / 区域与证据 → 原因 / 影响假设 → 状态 → 优化动作 → 验收方法。状态为通过 / 未通过 / 待执行 / 无法判断 / 不适用。方案阶段无成图时只能评价设计约束，成图验收待执行；没有图片也不停止事实整理和条件策划。

主图使用场景与情绪价值服从适用官方要求；混合光源以物理相容为准，不改真实冷白或暖黄灯色。规则结果映射到现有视觉量表与 P0 / P1 / P2，不创建第二套分数，也不把高分解释为 CTR / CVR 已改善。

## 灯牌行业视觉判断规则

### 字符、组合与售卖内容

- 优先检查数字 / 字母轮廓、方向、顺序、开口和字间距；缩略图中也应可识别，不能镜像、重写或变形。
- 单字符、双位数字和词组按实际 SKU 展示。活动布景中的完整组合不等于包装包含整套；辅图明确组合示意和售卖数量，主图遵循官方要求。
- 保留灯泡 / 灯点数量与布局、板体结构、接缝、底座和实际支撑。未确认数量时使用真实素材，不自行补齐灯点。

### KT 板材质与真实尺度

- 保留真实表面、板厚、边缘、切口和装配方式，不把 KT 板渲染成不存在的材质质感。
- 高度、宽度、厚度和人物 / 家具尺度有依据才表达；使用美国用户易理解的单位，换算须准确。
- 不通过人物缩小、夸张透视或低角度暗示更大尺寸；数字 / 字母不同宽度不能机械等宽。
- 未知的折叠、拼装、供电方式、遥控、调光及配件不能补造；功能图依据已确认说明。

### 发光表现与摄影真实感

- 用灯点、轮廓、板体和环境关系展示亮灯效果，避免过曝使字符和材质消失。
- 明暗、色温、灯点布局与真实产品一致；只有已确认变色能力才展示不同灯色。
- 灯点光晕适度，接触阴影、邻近表面的照明与光源强度相容；不把灯牌表现为未经证实的整场照明设备。
- 区分白天识别和低光氛围。亮灯 / 未亮灯对比记录条件，不靠不公平曝光夸大亮度；没有拍摄依据时不宣称亮度数值。

### 活动场景与购买信号

- 生日：数字准确对应用户提供的年龄或纪念数字，主体不被布景遮挡；不能随意换数字。
- 婚礼：字母、姓名或词组与已确认售卖内容一致，营造真实活动空间；不能暗示单字母 SKU 包含整个词组。
- 求婚：仅在相关字符 / 词组与组合能力确认后策划表达，不借氛围新增字符或配件。
- 毕业：年份与实际项目目标一致，不默认当前年份；节日使用用户指定的活动主题。
- 人物、花艺、气球与桌椅服务于尺度和活动解释，不抢夺灯牌主体，不误导为随附物品。
- 从输入证据判断可能的购买信号：字符易读、大小可理解、亮灯效果可信、组合清楚、安装可理解、活动场景匹配。不得直接称为全市场已验证偏好。
- 使用有依据的功能说明，未经确认不表达防水、户外适用、儿童操作、电气安全或耐用性承诺；场景不得暗示未经支持的使用条件。

### 竞品与差异化

- 核心市场样本只选美国站 KT 板发光灯牌；按数字 / 字母、单件 / 组合、尺寸、活动用途、价位和图片角色分层。
- 非同材质或售卖形式不可比的参考不进入主流统计；不引入其他 Amazon 品类作策略依据。
- 优先修复字符识别、真实尺度、亮灯真实性和数量理解；差异化可来自更清晰的场景叙事、视角、信息层级和经证实的产品特点。
- 80/20 原则不允许改变字符、板体、灯点、颜色、尺寸、功能与数量来制造记忆点。

## 七步执行流程

### Step 1：图片视觉诊断

先执行产品专属规则的四项前置判断，再进行视觉诊断；新品缺成图时先锁定产品事实与制作限制，不虚构当前图问题。

先独立查看当前图与参考图，再做对比。检查主体识别、产品比例、构图层级、前中背景、光影、人物、场景、文字与移动端可读性；检查整个图片组的信息覆盖和顺序。

优先应用灯牌专属检查：字符识别、SKU 组合、KT 板质感、真实高度、灯点 / 光晕 / 曝光、支撑与安装、活动用途及配件边界。

按 Visual Quality Rules 记录当前图及参考图的证据与状态。优秀参考也可能有人物遮字、主体偏弱或位置不适用，保留可学习方法并说明不可迁移部分。

输出问题、具体区域或文字证据、影响机制假设、置信度与限制。新品无成品图时分析产品素材及缺口，不虚构现有图片问题。

### Step 2：市场主流审美判断

使用 [市场与策略模板](templates/market-strategy-template.md)。按同品类、人群、价位和图片角色对齐参考，按 Listing 去重，记录模式出现次数 / 有效样本数。区分样本常见、购买信号假设与实测有效。

这里的品类只指本 Skill 范围内的 KT 板数字 / 字母灯牌细分，不扩大到其他商品。

有证据才称 TOP / 高销量；单期样本不判断时间趋势。缺少代表性时只输出局部参考，不声称市场共识。“市场验证”指样本与依据检查，不等于已经完成流量实验。

### Step 3：差异化策略判断

解释“为什么不好”，选择主流修复、受控差异化、先修复后差异化或证据不足。列出必须保持、市场共识、可突破项及依据。

遵循 80% 主流、20% 差异化启发式，不机械计算画面比例。基础识别不完整时先修复；没有真实优势时不强造记忆点。输出策略 ID、风险、预期机制和验证方法。

### Step 4：优化优先级排序

P0 为已证实的事实错误、误导或规则冲突；P1 为识别、关键信息、可读性或真实性问题；P2 为细节与探索。规则未核实不认定违规。

同级按证据、预期影响、成本和依赖排序，说明理由。新品排序对象为制作任务与补充素材，而非不存在的旧图问题。

### Step 5：生成修改方案

逐图输出保留、删除、新增、调整，以及构图、产品尺度、场景、光影、素材、英文文案和验收方法。每项关联问题、证据与策略。确定局部编辑、重拍、合成或重做；新品输出逐图制作 Brief。

方案追加规则 ID、要修复的具体问题和成图验收标准，体现“为什么优秀 / 为什么需要修改”，不只列风格词。

### Step 6：生成 AI 图片修改 Prompt

使用 [Prompt 模板](templates/image-prompt-template.md)，旧图默认编辑，需重做时明确声明；新品生成或合成必须引用真实产品素材。

输出英文 Prompt、中文摘要、源图、参考图用途、修改区域、蒙版需求、产品保真、市场保留项与突破项。缺少制作必需信息时标记 `blocked` 或 `draft`，不交付为可执行成品 Prompt。按工具实际能力给参数；文案单独后期排版。

本步编写 Prompt，不默认生成图片。用户另行请求出图时检查模型能力、素材和编辑范围再执行；不得声称 Prompt 已被模型验证。

### Step 7：输出验收标准

使用 [验收模板](templates/acceptance-template.md)，给出逐任务标准、检查方法和状态。区分方案完整性、实际改图视觉验收与业务效果验证。

实际成图后按同一组适用规则复查，并记录前后变化与剩余缺陷；主图发布前提和真实性未核实的部分不能因整体好看而判通过。

只有方案时，改图验收为待执行；仅有原图时不声称优化后已通过。无流量数据时不认定 CTR / CVR 改善。反馈有数据时校验口径和混杂因素；历史经验仅引用用户提供或获授权访问的资料，不声称已入库。

## 固定交付

- 差转优：[报告模板](templates/bad-to-good-report-template.md)。
- 新品：[报告模板](templates/new-listing-report-template.md)。
- 保留模板核心章节，缺失项写明原因；删除占位示例，不能用占位文字冒充结论。
- 正式结论链：图片观察 → 证据 → 原因假设 → 市场 / 差异化决策 → 任务 → Prompt → 验收。
- 完成所有可独立执行步骤后交付。只有确实阻塞的图片或事实才请求补充，不为可推断偏好反复询问。

## 完成条件

七步各有产物或明确的缺失 / 不适用状态；两类项目必需输出齐全；所有修改均可追溯；关键未确认事实未进入成品卖点；未执行的出图、移动端检查和业务实验明确列为待执行。

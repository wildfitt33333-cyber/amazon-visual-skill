# Benchmark Case 调用测试流程

## 1. 目标与测试边界

验证 Amazon Marquee Visual Director 能否根据产品、年龄阶段、场景与视觉目标，按 [Benchmark 索引](../case-library/benchmark-cases/index.md)选择合适参考，并识别不匹配、缺失及冲突。

本文件是四组输入的人工调用测试规范，不是新增 Benchmark 案例，不写入案例库。验证对象为路由与理由，不验证出图质量、Amazon 发布合规或 CTR / CVR。当前没有自动匹配程序；预期答案不能当作自动测试通过证据。

默认测试范围为 Amazon US；原始输入未说明材质、灯色、套装及供电时标记未知。可以生成候选匹配，但不能假称 KT 板或功能已确认。年龄数字不自动等于人物实际年龄。

## 2. 执行方法

1. 读取 [Skill](../skills/amazon-visual-optimization/SKILL.md)、案例索引及选定案例全文。
2. 逐条提供下列原始需求，不预先向待评 Agent 展示预期答案。
3. 先整理四项输入，再识别图片角色、事实缺失与冲突。
4. 输出推荐案例、推荐原因、可参考元素、应避免问题；额外明确匹配状态、待确认项及原图可用性。
5. 按本文件的预期断言逐项检查，保留实际原始输出；不同措辞只要语义一致可通过。
6. 输入矛盾允许部分分析，受影响的最终制作保持受阻；不以必须选出主参考作为通过条件。

### 固定输入格式

```text
产品类型 / 字符 / 高度：
年龄阶段 / 购买者与使用者（未知保留未知）：
使用场景 / 图片位置：
视觉目标：
市场、材质、灯色、包装和环境支持资料（未提供则标记）：
```

### 固定输出格式

```text
推荐 Benchmark：案例 ID；BM-004 必须附子图 ID
匹配状态：primary / conditional / technique_only / no_match
推荐原因：产品、场景、年龄或需求依据
可参考视觉元素：具体构图、层级、场景或光影方法
应避免问题：不匹配表达、事实迁移与视觉缺陷
待确认 / 受阻项：角色、材质、字符、尺寸、使用条件等
引用：案例路径与章节；实际原图是否可访问
```

## 3. 测试输入与预期判断

### 测试 1：4FT 数字 60，高级家庭生日场景，美国站主图

**原始需求**：4FT 数字 60 生日灯，美国站主图，需要高级家庭生日场景。

| 输入项 | 整理要求 |
| --- | --- |
| 产品类型 | number-light；60；4FT，件数待确认 |
| 年龄阶段 | 成人生日主题；数字提示 60 主题，但人物实际年龄、性别未提供，不擅自指定 |
| 使用场景 | 家庭生日；Amazon US 主图 |
| 视觉目标 | 高级生活场景、产品主体与家庭真实感 |

**推荐 Benchmark**：[BM-003](../case-library/benchmark-cases/creative-scene-reference/birthday/benchmark-003-50th-birthday-home-lifestyle.md)，作为家庭生活场景的 `conditional` 候选；主图的场景呈现要求需先核实，不作为直接发布范本。

**推荐原因**：数字生日、成人家庭主题和生活方式表达匹配。原案例为数字 50 / 3FT，本任务为 60 / 4FT，必须使用当前 SKU 事实；不是因为 A 级就忽略差异。

**应参考**：客厅空间层次、产品 / 人物并列、自然中性色的条件方案、柔和环境光、装饰辅助层级。

**应避免**：照搬 50、3FT、女性身份或饮酒元素；把 40%–50% 变为固定占比；用人物缩小夸大 4FT；断言成人必须低饱和；直接把有生活背景的图判为合规主图。

**待确认**：主图是否指 Amazon 搜索首图、对应官方要求、人物设定、材质与组合数量。若确为受限制的首图，应分别给出合规产品展示方向和条件性的场景副图建议，不能悄悄把用户位置改成副图。未确认前不交付“可发布场景主图”。

**通过断言**：BM-003 被识别为场景候选；识别主图 / 场景冲突与 3FT → 4FT 差异；不以 BM-001 的 4FT 高度取代成人数字场景匹配；不推断人物真实年龄。

### 测试 2：4FT MARRY ME，海边求婚

**原始需求**：4FT MARRY ME 灯牌，需要海边求婚场景。

| 输入项 | 整理要求 |
| --- | --- |
| 产品类型 | letter-light；MARRY ME；4FT，完整套装待确认 |
| 年龄阶段 | 未提供；按求婚角色判断，不指定年龄或身份 |
| 使用场景 | 海边求婚；图片位置未知 |
| 视觉目标 | 浪漫事件、动线、沉浸式求婚表达；属于需求解读 |

**推荐 Benchmark**：[BM-004](../case-library/benchmark-cases/creative-scene-reference/proposal-and-wedding/benchmark-004-romantic-marquee-scene-set.md)，子场景 A／**BM-004-IMG-01**。主题最匹配，当前为 `conditional`，实际海边使用与产品事实须核实。

**推荐原因**：同词组与同事件阶段，第一视角、花艺通道和日落叙事符合海边求婚任务。A 原参考 3FT，本任务 4FT；不因 B 是 4FT 就改选户外婚礼。

**应参考**：牵手入口、背影引导、通道动线、花艺框景、暖色环境与真实灯光相容、产品作为仪式中心。

**应避免**：照搬 A 中央人物遮挡字母的缺陷；新增字符或整套配件；虚增尺寸；由海边场景推断防水、耐候、无线或安全能力；按参考强改本品灯色；把 A 独立新建成另一个案例。

**待确认**：材质、套装、户外说明、支撑、供电、真实灯色及图片位置。关键条件不足时保留场景候选与受阻项，不声称可落地或合规。

**通过断言**：返回组级 BM-004 + A 子图 ID；指出高度差异和海边条件；避免 B/C 作为主选；未知年龄不阻塞候选路由。

### 测试 3：3FT 数字 16，Teen 生日派对

**原始需求**：3FT 数字 16 灯，需要 Teen 生日派对场景。

| 输入项 | 整理要求 |
| --- | --- |
| 产品类型 | number-light；16；3FT，组合数量待确认 |
| 年龄阶段 | Teen 已明确；16 为生日数字，人物年龄与性别仍按输入确认 |
| 使用场景 | Teen 生日派对；图片位置未知 |
| 视觉目标 | 生活化庆祝、数字辨识、自然人物互动；属于需求解读 |

**推荐 Benchmark**：[BM-002](../case-library/benchmark-cases/benchmark-002-3ft-teen-birthday-number-16.md)。它是语义上的最匹配主候选；未确认 KT 板、角色等时输出 `conditional`，事实与场景位置确认后可为 `primary`。

**推荐原因**：数字、参考高度与 Teen 活动同时匹配，优先于儿童字母或成人 50 场景。

**应参考**：清楚展示数字顺序、坐姿自然互动、气球框景、空间深度、人物 / 产品 / 装饰角色分工。

**应避免**：机械使用黑白金、默认女孩身份、装饰压过数字、人物肢体遮挡轮廓、套装数量误导、将原副图当搜索主图合规范本、宣称 CTR / CVR 已提高。

**待确认**：材质、字符套装、人物设定、活动主题与图片位置。不需为了这些缺失放弃明显的案例候选。

**通过断言**：推荐 BM-002，并解释三项匹配；不因 BM-003 为 A 级而优先；保留角色与产品事实待确认；不将 Teen 定位当作强制配色 / 性别规则。

### 测试 4：3FT 数字 9，8 岁男孩游戏生日

**原始需求**：3FT 数字 9 灯，需要 8 岁男孩游戏生日场景。

| 输入项 | 整理要求 |
| --- | --- |
| 产品类型 | number-light；9；3FT，不能自动改成 8 |
| 年龄阶段 | kids；8 岁男孩，来自明确输入，不由图片推断 |
| 使用场景 | 儿童游戏主题生日；图片位置未知 |
| 视觉目标 | 游戏主题与儿童生日生活感、产品识别；具体游戏与风格未提供 |

**输入冲突**：售卖数字 9 与 8 岁生日年龄不一致。需确认产品是否应为 8、是否为 9 岁生日，或数字 9 是否另有非年龄用途。提出这一必要澄清，不默认改字符，也不认为年龄无条件决定 SKU。

**推荐 Benchmark**：`no_match`，当前没有完整的儿童数字游戏生日主参考；可给两项 `technique_only`：

- [BM-001](../case-library/benchmark-cases/benchmark-001-4ft-birthday-letter-a.md)：只借鉴儿童家庭氛围、人物辅助情绪和主体层级。原产品是字母 A / 4FT，不是数字或游戏主题范本。
- [BM-002](../case-library/benchmark-cases/benchmark-002-3ft-teen-birthday-number-16.md)：只借鉴数字识别、组合与场景分工。原活动为 Teen，不迁移其人群、配色和人物。

**推荐原因**：索引允许跨维度方法借鉴，也允许无主匹配；年龄 / SKU 冲突与无游戏主题标杆不能通过强选一个案例消除。

**应参考**：产品先读、人物不遮数字、背景服务活动、按真实 3FT 资料控制尺度；颜色和人物动作依据实际游戏主题及用户输入。

**应避免**：默默把 9 改成 8；新增“儿童游戏生日标杆”；将 BM-001 标为同产品主参考；机械套 Teen 女孩或黑白金；默认男孩喜欢固定颜色；补造具体游戏 IP 或可售配件。

**待确认 / 受阻项**：数字 / 年龄关系、具体游戏主题及素材授权、材质与 SKU、图片角色。完成冲突记录和方法建议，但暂停受影响的成品文案、年龄数字表达与可执行场景 Prompt。

**通过断言**：主动识别 9 / 8 冲突；允许无完整主参考；BM-001 / BM-002 仅限方法借鉴；不创建新案例，不静默更改产品或年龄。

## 4. 统一判定标准

每组逐项判定通过 / 未通过 / 未执行，不用总分掩盖关键错误：

| 检查项 | 通过条件 |
| --- | --- |
| 四项输入 | 产品、年龄阶段、场景、视觉目标有记录；未知不编造 |
| 推荐与状态 | 案例 ID、组内 ID、主 / 条件 / 方法 / 无匹配含义正确 |
| 原因与元素 | 具体关联用户任务，包含允许借鉴的视觉方法 |
| 差异与避免 | 明确尺寸、产品、年龄、位置或环境差异，不照搬事实 |
| 冲突处理 | 测试 1 的主图场景限制、测试 4 的字符年龄冲突被识别 |
| 验证诚实性 | 不宣称重新看过不可访问图片、合规已通过或经营改善 |
| 案例数量 | 始终为 BM-001–BM-004，BM-004 不拆组 |

单组通过需全部适用检查项通过。遗漏关键冲突、默改 SKU、虚构效果或新增标杆均判未通过，即使推荐 ID 正确。

## 6. 测试 1 实际模拟记录

执行日期：2026-10-09。输入：4FT 数字 60；白色 KT 板 + 暖黄色灯泡；Amazon US 主图；高级家庭生日庆祝场景。材质与灯光作为用户提供信息，未独立实测。人物年龄、性别、包装套装、供电、宽度与安装资料未提供。

执行方式：当前 Agent 阅读 Skill、索引、BM-003 全文及相关知识条目后进行模拟。已经接触预期答案，因此这是引导式执行与人工规则核对，不能当作独立匹配能力盲测或自动测试。

### 实际输出

1. **是否调用**：是，调用场景策划参考；不认定其为可直接发布的 Amazon 主图范本。
2. **调用案例**：BM-003，匹配状态 `conditional`。不调用 BM-001、BM-002 或 BM-004 作为本任务主参考。
3. **选择原因**：数字生日、成人家庭主题、生活方式摄影目标匹配。BM-003 为 50 / 3FT，本任务为 60 / 4FT，只借鉴空间、层级与光影方法；不迁移字符、尺寸、女性身份或饮酒元素。成年生日为当前主题假设，不把数字直接认证为人物实际年龄。
4. **场景设计建议**：条件场景方案使用真实客厅、奶油白与木色基础，可少量鼠尾草绿点缀；60 位于沙发旁前方的地面，前景少量花艺，中景产品，背景自然家庭互动。人物角色按实际输入确认，不能遮住数字。柔和窗光风格配合真实暖黄灯点，保留板体和边缘。若“主图”指搜索首图，先核实规则，优先准备纯白产品展示方向；家庭布景作为另行建议的场景副图方案，不擅自更改用户位置要求。
5. **产品突出策略**：6、0 顺序正确，轮廓与内孔完整；用构图、留白、背景简化和主体对比建立第一视觉。4FT 对应 121.92 cm，真实尺度按产品资料，不缩小人物或拉伸灯牌。保留实际板体、灯点、灯色与支撑；灯光不吞字形。只展示实际售卖件数，不照搬 BM-003 未定义口径的 40%–50% 占比。
6. **避免问题**：将生活场景直接认证为合规主图；套用 50 / 3FT；默认女性、饮酒或固定年龄审美；装饰过量、人物抢主体；夸大尺寸、过曝光晕、改成其他材质；暗示未知功能、套装和安全能力；宣称 CTR / CVR 已提高。
